# Memory decompilation — 2026-10-05

All 34 functions in `ios/memory.c` are reconstructed and match the original
PS2 object. C accounts for 11,772 of its 11,816 code bytes (99.63%, including
function alignment and excluding 44 bytes of explicit architecture instructions).
Estimated main EE C coverage is 78,604 / 2,573,952 bytes, or 3.05383%.

The completed functions include the public allocation/freeing wrappers, DMA
transfers, reallocation, partial freeing, partition initialization and queries,
garbage collection callbacks, link consistency checks, and diagnostic output.
The block allocator preserves aligned payloads, split remainders, and free-list
links. Full freeing merges adjacent free blocks; partition creation initializes
the bucket array and its first free block.
The allocation wrappers preserve the caller PC from the PS2 `ra` register.
Packed block addresses, sizes, partition ownership, and callbacks use the original
24-bit fields. Private views of these fields preserve the PS2 compiler's layout;
compile-time checks require a 36-byte block view, an 8-byte bucket, and a 12-byte
partition view.

No `INCLUDE_ASM` functions remain in this file. The final internal routines cover
sorted free-list insertion, aligned allocation and splitting, garbage-allocation
compaction, full freeing with neighbor coalescing, and partition creation.

## Compiler constraints and architecture instructions

Named-register variables and empty assembly operands preserve EE-GCC 2.96 register
lifetimes and scheduling. These constraints emit no instructions; the arithmetic,
metadata updates, control flow, and MMIO accesses are expressed in C. Volatile
accesses preserve separately visible DMA operations and allocator accounting
stores present in the original code.

The legacy EE assembler can corrupt the HI16 opcode when expanding a symbolic
`lb` macro, depending on its logical input filename. A `.org .` directive before
the partition-creation and compaction lookups starts a new fragment and fixes this
deterministically.
It emits no instructions or padding; the lookup remains a C expression.

44 bytes remain explicit PS2 instructions: two `break 0` corruption traps (8 bytes)
and the `sync` / `bc0f` DMA completion wait with its original pipeline delays
(36 bytes). These bytes are excluded from C progress. The return from the DMA wait
is generated by the C compiler. The local ISA manifest records the precise ranges.
